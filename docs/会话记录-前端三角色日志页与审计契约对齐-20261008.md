## 二、三步的共同架构模式

三步都沿用同一套分层，保持可复制：

- **视图层**：`el-container` 深色顶栏 + 220px 侧边 `el-menu` + 主内容区按 `activeMenu` 切换；其余业务功能保留 `el-empty` 占位。
- **组件层**：全量日志表格（筛选 + 分页）与档案/单据追溯日志子组件（Props 传入、`watch` 切换自动重载）分离。
- **权限红线**：靠路由守卫 `meta.roles`（`router/index.ts` L36/42/48 分别 `ADMIN`/`STAFF`/`AUDITOR`）拦截，页面内不重复判权。
- **兜底策略**：优先请求真实接口，失败时 `ElMessage` 透后端 message 并落入原型示例数据 + 提示条，筛选与分页在兜底模式走本地逻辑保持可交互。

## 三、关键转折：`action_type` 契约错位

### 3.1 核查证据（后端事实源）

| 项 | 后端真实定义 | 前端第一步~第三步实现 |
|---|---|---|
| 操作类型字段 | `action`（`AuditAction.java` 枚举 + `audit_log.action VARCHAR(50)`，存 `枚举.name()`） | `action_type` ❌ |
| 取值 | 英文码 `SUBMIT / AUDIT_APPROVE / AUDIT_REJECT / REVIEW_APPROVE / REVIEW_REJECT / DECISION_APPROVE / DECISION_REJECT` | 中文动作名 ❌ |
| 目标对象 | `entity_type` + `entity_id`（`EntityType`：SUPPLIER / PERFORMANCE_EVALUATION / PERFORMANCE_EVALUATION_DRAFT / LIFECYCLE_REQUEST / USER） | `supplier_id` / `supplier_name` / `target_object` ❌ |
| 状态 | `old_status` / `new_status` 存 `SupplierStatus`/`LifecycleRequestStatus`/`EvaluationStatus` 码 | 中文「待审核/正常」等 ❌ |
| 查询参数 | `GET /audit-logs` 仅消费 `entity_type` / `entity_id` / `page` / `page_size`（`AuditLogController`） | 传 `operator_name` / `action_type` / `start_date` 等 ❌ |

### 3.2 危害

中文值做等值查询永不匹配（列表恒空）；按中文 key 的 `el-tag` 颜色映射全量落兜底分支；后端一旦补接口即需二次返工。

### 3.3 用户决策

四选项中选择「改对齐后端」：接口层只用后端枚举码，UI 保留中文映射展示。

### 3.4 落地的分层规约

- `src/constants/auditDictionary.ts`（新增 275 行）：码值（`as const`，项目开 `erasableSyntaxOnly` 禁用 `enum`）+ `*_LABEL_CN` 文案表 + `*_TAG_TYPE` 颜色表 + `getActionLabel/getStatusLabel/getStatusTagType/formatCreatedAt/formatOperator` 解析函数 + `AUDITOR_/ALL_/STAFF_ACTION_OPTIONS` 筛选选项。
- `src/constants/auditLogView.ts`（新增 45 行）：`export * from auditDictionary`，补两项视图专属降级解析 `getEntityLabelOrId`（后端不返回名称时退化为「对象类型 + ID」）与 `resolveActionLabel/TagType`。
- 未知码策略：文案原样回显、标签色兜底 `info`（旧实现兜底 `danger` 会满屏红）。
- 跨域同码不同义（`APPROVED` 生命周期域「已批准」vs 绩效域「已复核通过」）：状态文案按域拆三张表，由 `getStatusLabel(code, entity_type)` 选口径。
- `el-select` 的 `:value` 绑码、`:label` 显中文；表格单元格渲染 `{{ getActionLabel(row.action) }}`。
- 示例数据整体重写为枚举码存储，并按后端真实写入规则区分 `entity_type`（准入审核→SUPPLIER、终审决策→LIFECYCLE_REQUEST、绩效复核→PERFORMANCE_EVALUATION）。
- 视图侧供应商状态从中文字面量改为码（`SUPPLIER_STATUS_CODES`），演示字段 `tax_id` 纠正为 api-spec 的 `tax_no`。

## 六、遗留待办与风险

1. **`UPDATE_ROLE` 命名与后端不一致（新发现，建议优先修）**：`types/admin-log.ts` 的 `ADMIN_PENDING_ACTION` 用 `UPDATE_ROLE`，而后端 `AuditAction` 与 api-spec §5/§6 已定义为 `UPDATE_USER`（角色/资料修改统一归 `UPDATE_USER`）。改法：码值替换为 `UPDATE_USER`，中文 label「调整用户角色」可保留。
2. **字典缺 4 个用户管理动作码**：后端 `AuditAction` 现已含 `CREATE_USER / UPDATE_USER / ENABLE_USER / DISABLE_USER`（提交 `d2c8578`，见《会话记录-审计日志用户管理动作-20261008.md》），但 `auditDictionary.ts` 的 `AUDIT_ACTION` 仍只列 7 个审批码 —— 契约对齐轮当时基于旧结论「后端未定义」。应补入这 4 个码及其 `ACTION_LABEL_CN` / `ACTION_TAG_TYPE`，并删除 `ADMIN_PENDING_ACTION` 的「待后端补充」注释。
3. **后端筛选参数缺口**（前端已按扩展参数预发，被后端忽略，组件侧本地过滤兜底）：`action`、`entity_name`（目标供应商名模糊）、`operator_name`、`start_date` / `end_date`。
4. **按供应商聚合追溯日志无法只靠 `entity_id`**：终审决策记录的是 `LIFECYCLE_REQUEST`（`entity_id`=申请单 ID），需后端补 `supplier_id` 维度查询；当前兜底模式按对象名匹配。
5. **`/audit-logs` 无 `entity_name` 返回**：真实接口打通后「目标供应商」列会退化为「供应商档案 #ID」，需后端联表补名称字段。
6. **业务功能仍为占位**（截至 2026-10-09 更新）：用户账号管理**已实现**（`components/admin/UserAccountView.vue`，后端 `UserController` 也已合入提交 `f3d1acc`）；绩效录入、待办审核签署/终审决策弹窗未实现。「角色与权限维护」经任务确认**不列入导航**，已从管理员控制台侧边菜单移除。
7. **后端分页未生效（已修）**：曾发现 `MybatisPlusConfig` 只注册 `OptimisticLockerInnerInterceptor`、缺 `PaginationInnerInterceptor`，导致 `selectPage` 不加 `LIMIT`、`total` 恒为 0，影响 `GET /users` 与 `GET /audit-logs`（8081 实测 `page_size=2` 返回 3 条 / `total=0` 印证）。现已补 `new PaginationInnerInterceptor(DbType.MYSQL)` 并实测恢复正常（`page_size=2` → 2 条 / `total=6`）；前端用户列表当前的「整表拉取（page_size=100）+ 本地筛选」仍可工作，待用户量接近该上限时应改为真服务端分页（需后端同时支持 keyword/status 筛选参数）。

## 七、可复用教训

- **原型 HTML 的字段名与中文选项不能直接当作 API 契约**。三步任务书均照搬原型命名（`action_type`/`target_object`/`detail`）与中文取值，须先核对后端枚举源码 + Controller 实际入参再动手；本轮等于把三步的一次性返工前置成一条检查项。
- **前后端契约需双向核对，且文档本身可能过时**：`docs/SRM 后端数据库表设计.md` §8 的 `result` 曾写 `SUCCESS/FAILED`，与代码 `AuditResult`（`SUCCESS/REJECTED`）冲突，以代码 + api-spec 为准。
- **IDE 附件 diff 与磁盘可能不一致**（本次「启动」指令前再次遇到：附件显示 `UserListView.vue` 回退旧版，磁盘实为重构版）：改动前必须用 `grep`/`git status` 核实磁盘真实状态，不可据附件 diff 覆盖。
