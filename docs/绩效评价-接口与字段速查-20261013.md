## 一、设计铁律（凌驾所有接口）

1. **防篡改**：前端只能提交**客观事实**，入参 DTO 物理上不存在分数/评级字段；五维分、总分、评级全部由后端 `PerformanceScoreCalculator` 按固定权重算出，不可配置、不可被请求影响。
2. **无草稿态**：STAFF 一次 POST 即算分落 `PENDING_REVIEW`（提交即锁死）。TDD §6 的 `PerformanceEvaluationDraft` 仅是后端内部暂存表，**不暴露任何草稿 API**。
3. **一个考核周期一张在途单**：同 `supplier_id`+同周期存在 `PENDING_REVIEW`/`RETURNED` 在途单再建 → 40902；DB 生成列 `uk_supplier_active_period` 并发兜底。
4. **归档即永久**：`APPROVED` 后不可再编辑；**无独立历史表**（schema 中不存在，也不得新增）。
5. **评价不改状态**：C/D 级只置 `risk_warning`，供应商状态迁移永远走生命周期申请流程（§3），评价接口物理无供应商状态句柄。

## 二、状态机（评价单三态）

```
（POST 创建即算分，无草稿）
   │ STAFF
   ▼
PENDING_REVIEW ──P3 review APPROVE──▶ APPROVED（归档终态，永久不可变）
   ▲    │
   │    └──P3 review REJECT──▶ RETURNED ──P2 PUT 改事实重提（同 id 重新算分）──▶ PENDING_REVIEW
   └────┘
```

`EvaluationStatus = 'PENDING_REVIEW' | 'APPROVED' | 'RETURNED'`
**勿混用**：与供应商状态 `PENDING_REVIEW`（六态之一）、资质状态 `PENDING`（三态）是**三个不同枚举**，仅码值字面部分重叠。

## 三、接口总表（5 个）

| # | 方法 路径 | 角色 | 一句话 |
|---|---|---|---|
| P1 | POST `/performance/evaluations` | STAFF | 一步发起评价：`mode=manual` 校验事实 / `mode=mock` 服务端确定性生成事实（前端夹带的 fact_record 被**忽略而非报错**），后端算分落 `PENDING_REVIEW` |
| P2 | PUT `/performance/evaluations/{id}` | STAFF 本人 | 仅 `RETURNED` 可全量替换 `fact_record` 重提，重新算分，沿用同一 `id` |
| P3 | POST `/performance/evaluations/{id}/review` | AUDITOR | 复核：`APPROVE` 归档（联动刷新供应商 `latest_performance_grade`/`risk_warning`）/ `REJECT` 退回 |
| P4 | GET `/performance/evaluations` | ALL（§0 隔离） | 分页列表：`supplier_id?` `status?` `page` `page_size` |
| P5 | GET `/performance/evaluations/{id}` | ALL | 详情 |

## 四、逐接口入参 / 出参 / 错误码

### P1 · POST `/performance/evaluations`

**入参** `PerformanceEvaluationCreateRequest`：

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `supplier_id` | number | ✅ | 被评供应商 |
| `period_start` | string | ✅ | `yyyy-MM-dd`（周期无独立编码列，start+end 表达） |
| `period_end` | string | ✅ | 周期止 |
| `mode` | string | ✅ | `'manual'` / `'mock'` |
| `fact_record` | object | mode=manual ✅ | 8 事实字段（表六），`ManualFactInputAdapter` 校验：全非负、`qc_failed_batches ≤ qc_total_batches`、`delayed_batches ≤ total_batches` |

**出参**：`data` = PerformanceEvaluationResponse（表七）
**错误码**：`40001` 事实校验失败｜`40902` 同周期在途冲突（应用层预检 + DB `DuplicateKey` 转译双保险）
**留痕**：`action=SUBMIT`、`entity_type=PERFORMANCE_EVALUATION`

### P2 · PUT `/performance/evaluations/{id}`

**入参** `PerformanceEvaluationUpdateRequest`：`fact_record`✅（8 字段全量替换）+ `version`✅
**出参**：PerformanceEvaluationResponse（`RETURNED → PENDING_REVIEW`，同 id 不新建）
**错误码**：`40302` 非本人/非 RETURNED｜`40001` 事实校验｜`40901` 版本不匹配
**留痕**：重提动作（`SUBMIT` 类，实现批次定稿）

### P3 · POST `/performance/evaluations/{id}/review`

**入参** `PerformanceReviewDecisionRequest`：

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `version` | number | ✅ | 乐观锁，不匹配 40901 |
| `decision` | string | ✅ | `APPROVE` / `REJECT` |
| `comment` | string | REJECT ✅ | 复核意见（落 `review_comment VARCHAR(1000)`） |

**出参**：PerformanceEvaluationResponse
**错误码**（20261013 显式化）：`40302` 非法状态复核（已归档/不存在/已被并发复审，`RoleGuard.requireStatusAllowed`）｜`40901` 版本不匹配
**留痕**：`action=REVIEW_APPROVE/REVIEW_REJECT` + `entity_type=PERFORMANCE_EVALUATION`（**方案甲一码多域**：同码亦服务资质审批，前端文案按 entity_type 分流，绩效域显「绩效复核」系文案）

### P4 / P5 · GET 列表与详情

**入参**：P4 query `supplier_id?` `status?` `page` `page_size`；P5 路径 `id`
**出参**：P4 = `{ list: PerformanceEvaluationResponse[], total, page, page_size }`；P5 = PerformanceEvaluationResponse
**索引支撑已就绪**：`idx_supplier_id`、`idx_status`、`idx_supplier_status`、`idx_supplier_period`、`idx_created_by`

## 五、字段总表

### 5.1 入站 `PerformanceFactRecord`（8 字段，防篡改：无分数通道）

| 字段 | 消费维度 | 备注 |
|---|---|---|
| `total_batches` | D 交付 | 分母；=0 触发零业务免考 D=100（**对称扩展，待回写 TDD，见 docs/上游文档docx治理备忘.md**） |
| `delayed_batches` | D | 逾期批次数 |
| `avg_delay_days` | D | 平均逾期天数 |
| `qc_total_batches` | Q 质量 | 分母；=0 则 Q=100 |
| `qc_failed_batches` | Q | 不合格批数 |
| `major_accidents` | Q | 重大事故数（每个 -50） |
| `price_deviation_rate` | P 价格 | 偏离率 %（×2 扣分） |
| `complaint_overtime_count` | S 服务 | 客诉超时次数（每次 -10） |

（**C 合规不在入参**：后端自动读现行 `APPROVED` 资质过期态；`PENDING/REJECTED` 件不参与）

### 5.2 出站 `PerformanceEvaluationResponse`（16 字段，20261013 起含 mode）

`id, supplier_id, period_start, period_end, **mode**（只读回显取数模式，写接口不接受本字段）, fact_record（8 字段嵌套对象）, result（嵌套 9 字段）, status, version, created_by, created_by_name（JOIN 派生）, created_at, updated_at, reviewed_by?, reviewed_at?, review_comment?`

`result` 嵌套 9 字段（= DB 平铺 9 列，Service 层组装）：

| 字段 | DB 列 | 类型 |
|---|---|---|
| `score_quality / score_delivery / score_price / score_service / score_compliance` | 同名 5 列 | DECIMAL(5,2) |
| `total_score` | `total_score` | DECIMAL(5,2) |
| `grade` | `grade VARCHAR(10)` | `A/B/C/D` |
| `quality_exempt` | `quality_exempt TINYINT(1)` | 免考共用一标（历史列名，MVP 不拆 delivery_exempt） |
| `risk_warning` | `risk_warning TINYINT(1)` | C/D 级或资质过期触发 |

DB 另有 `deleted`（逻辑删除）与 `active_period_key`（生成列，实体不映射）——**均不出现在任何 DTO**。

## 六、算分公式（后端硬编码，权重不可配置）

| 维度 | 权重 | 公式 |
|---|---|---|
| Q 质量 | 30% | `MAX(0, 100 - qc_failed/qc_total×100×1.5 - major_accidents×50)`；`qc_total=0 → 100 + exempt` |
| D 交付 | 25% | `MAX(0, 100 - delayed/total×100 - avg_delay_days×2)`；`total=0 → 100 + exempt`（待回写 TDD） |
| P 价格 | 20% | `MAX(0, 100 - price_deviation_rate×2)` |
| S 服务 | 15% | `MAX(0, 100 - complaint_overtime_count×10)` |
| C 合规 | 10% | 现行 APPROVED 资质全有效 `100`；任一过期 `0` + `risk_warning=true` |

`total = Q×0.30 + D×0.25 + P×0.20 + S×0.15 + C×0.10`；评级 `A≥90 / 80≤B<90 / 70≤C<80 / D<70`（边界值 90/80/70 必须有用例）。
联动：`C` 级→供应商维持状态仅预警；`D` 级→预警 + 人工走停用申请，**评价物理不自动改供应商状态**。

## 七、易错衔接点（实现与联调必读）

1. **`version` 四条取值链不可混用**（20261013 二次裁决后口径）：绩效 P2/P3 用 `PerformanceEvaluationResponse.version`；供应商 #2/#6/#7 用 `SupplierResponse.version`（#6 submit 自裁决后必带）；资质 #11 用 `QualificationResponse.version`（DDL④）；生命周期 #14 用 `LifecycleRequestResponse.version`（候选 A 新补出参）。
2. **一码多域（方案甲）**：`REVIEW_APPROVE/REVIEW_REJECT` 同时服务绩效复核与资质审批，靠 `entity_type` 区分；审计表禁写裸 `APPROVE`。
3. **status/grade 是 VARCHAR 无 DB 枚举约束**，且生成列 `active_period_key` 的防重逻辑依赖 `status IN ('PENDING_REVIEW','RETURNED')` 拼写正确——实现层必须常量化码值并测试断言，写错码值会静默绕过防重。
4. **result 嵌套是契约视图、DB 平铺**：Mapper 实体按 24 列平铺，组装放 Service/DTO 转换。
5. **mock 模式忽略前端 fact_record**（不报错），防借 mock 夹带分数；确定性种子=同 supplier_id+周期输出恒等。
6. **绩效留痕实体白名单成员**：`PERFORMANCE_EVALUATION` 属审核员四实体白名单（`AUDITOR_ENTITY_TYPES` 前端已就绪）。
