## 第 4 步 自动化测试（Verification Layer）

### 4.1 覆盖率指标说明：**85% 是最低门槛，不是合格标准**

| 指标 | 门槛值 | 本期实跑值（2026-10-13 10:20） | 解读 |
|---|---|---|---|
| JaCoCo 行覆盖 | ≥85% | **99.50%（396/398）** | 超门槛 14.5 个百分点 |
| JaCoCo 分支覆盖 | ≥85% | **100.00%（84/84）** | 全分支真实命中，无"凑数断言" |
| 用例总数 | 全绿 | **139**（Failures 0 / Errors 0 / Skipped 0） | `BUILD SUCCESS` |

**必须在汇报时讲清的三件事**：

1. **分母很小**：398 行只是**底座 + 用户管理**的代码量。业务功能（供应商/资质/状态机/绩效）代码为 0，所以 99.50% **不代表系统质量高到 99.5%**，只代表"已写的这一小块被测透了"。
2. **行/分支双达标才算数**：只看行覆盖会掩盖防御分支从未执行的事实；本项目分支覆盖 100% 意味着每个 `if` 的两个方向都有真实用例（含 `catch` 分支）。
3. **禁止反向凑数**：不允许为了百分比写"无断言的调用型测试"，也不允许降低门禁阈值（`AGENTS.md` 铁律）。历史数字"214 用例 / 行 99.63% / 分支 100%"因卡 1 撤销**已作废**，任何汇报不得再引用。

## 第 5 步 补充边界用例（Boundary Layer）—— 人工驱动的真实增益

### 5.1 已落地的边界用例（用例名可在仓库检索到，逐条真实）

| 边界场景 | 实存用例 | 为什么人工要补它 |
|---|---|---|
| **审计写入绝不影响主业务** | `recordNeverPropagatesMapperFailures`、`recordToleratesNullEntityTypeOperatorAndResult` | AI 默认让异常向上抛；业务要求留痕失败不能拖垮审核事务 |
| JWT 被篡改 / 过期 / 异密钥签名 / 乱码 | `validateTokenRejectsTamperedToken`、`...RejectsExpiredToken`、`...RejectsTokenSignedWithDifferentSecret`、`...RejectsGarbageAndNull` | 安全防线必须有负向用例，否则"验签"可能是空实现 |
| **双层 RBAC 兜底**：注解漏写时 Service 仍拦截 | `serviceLayerRoleGuardBlocksAdminEvenIfPreAuthorizeMissing` | 前端隐藏 + 注解是两层，人为遗漏 @PreAuthorize 是高频事故 |
| ADMIN 零业务写 / STAFF 业务写放行 | `adminRoleAccessesAdminOnlyEndpoint`、`staffRoleAccessesStaffOnlyEndpoint`、`serviceLayerRoleGuardPassesForStaffOnBusinessWrite` | 落实"管理与业务严格分离"矩阵 |
| 本人校验（`requireSelf`） | `serviceLayerSelfGuardPassesForOwner`、`updateStatusEnableSelfIsAllowedAndAuditsEnableUser` | 规则 A 私有在途区的第一道闸 |
| `entity_type` 逗号多值 / 单值等值 / 空白退化 | `listSupportsCommaSeparatedEntityTypesAsInFilter`、`listKeepsSingleValueTypeAsEqualityFilter`、`listIgnoresBlankCommaOnlyEntityTypeFilter` | 契约规定"解析后为空集退化为全量"，AI 极易写成"空集返回空列表" |
| **资质域留痕归属两分法** | `onboardingQualificationApprovalStayUnderSupplierDomain`（准入连带批复归 SUPPLIER）、`standaloneQualificationReviewIsRecordedUnderSupplierQualificationDomain`（存续期单独审批归资质域） | 方案甲裁决的落地护栏，防止实现走样 |
| 幂等更新不落库不留痕 | `updateStatusIdempotentDoesNotUpdateDbOrAudit`、`updateNoChangesDoesNotUpdateDbOrAudit`、`updateSelfWithoutRoleFieldIsAllowed` | 避免"重复点击产生脏留痕"污染审计追溯 |
| 操作人姓名缺失回退 + 撞号去重 | `listFallsBackToUsernameAndKeepsFirstOnDuplicateOperatorId` | `real_name` 为空时展示不能崩；批量反查 Map 合并冲突是真实 NPE 源 |
| 空表/空 count 防御 | `createTreatsNullCountAsUsernameAvailable`、`seedsWhenCountIsNullForDefensiveness`、`listWithoutFiltersSkipsUserLookupForEmptyPage` | Mapper 返回 null 与空页短路 |
| 拒绝响应由安全层出，而非业务 Advice | `accessDeniedIsHandledBySecurityLayerNotByAdvice` | 403 双通道处理，防止响应体格式二义 |
| 契约值防漂移 | `errorCodeCountMatchesContract`、`everyErrorCodeHasContractValue`、`auditEnumsCoverContractValues` | 把"契约"变成可执行断言，改码即红 |
| 三演示账号可用 | `allThreeDemoAccountsCanLogin` | 评审现场演示前置保障 |
| 停用账号不可登录 | `loadUserByUsernameThrowsWhenUserDisabled` | 与 40102 统一话术（不暴露用户名是否存在）配合 |

### 5.3 闭环链路总览（一页可讲完）

```
① 提示词约束          rules.md / AGENTS.md / agents 边界 / api-spec+schema SSOT / docx 只读
       ↓
② AI 生成             子代理在授权目录内产出（留痕可追溯；卡1 撤销事件亦如实登记）
       ↓
③ 人工业务复核        H1~H11 已固化裁决（外部评审意见 H12+ 待补）
       ↓
④ 自动化测试          139 用例 / 行 99.50% / 分支 100.00% / BUILD SUCCESS（85% 仅为门槛）
       ↓
⑤ 补充边界用例        已落地 15 类真实边界（§5.1）+ 8 项显式缺口登记（§5.2，含不可编写原因）
```

**方法学结论**：本闭环的价值不在"AI 写了多少代码"，而在**每一处 AI 判断都能被人工裁决（H 系列）或可执行断言（§5.1）钉住**；当被钉住的对象还不存在时，我们登记缺口并说明原因，而不是伪造覆盖率。
