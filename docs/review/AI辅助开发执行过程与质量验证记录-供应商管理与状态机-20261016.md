## 七、风险与改进项（均为建议，未完成）

1. **门禁覆盖盲区（风险）**：质量门禁挂在 Qoder PostToolUse Hook，`.git/hooks/` 为空——人工/IDE 直改代码可完全绕开 `check-coverage.sh`。**建议**：补 git pre-commit 或依赖 CI（`.github/workflows/` 已配置 qoder-action，但其对 PR 的实际拦截效果未在本地取证）。
2. **子代理自报与磁盘不一致（模块一开工轮实际发生）**：B1 子代理返回 `canceled by user`，但 `git status`+`ls` 实测其已落盘 14 个文件并改了 pom.xml/schema-h2.sql——**「被取消」不等于「未写入」**。**建议**：所有「已删除/已取消/已执行」类自报，验收方一律磁盘仲裁。
3. **测试运行工件不可回溯（风险）**：`target/` 工件每轮覆盖，10-14/10-15 各轮数字（218/294/468/473/502）无法独立复核。**建议**：门禁脚本输出归档到带时间戳的日志目录（如 `.run-logs/gate/`）。
4. **前端零自动化测试（缺口）**：验证面只有类型+构建。状态机前端「角色×归属×状态」三维门控（`isCreatedByMe`）目前只有代码审查级保证。**建议**：为 `api/lifecycle.ts` 请求构造与 `SupplierListView` 门控显隐补最小单测（vitest）。
5. **覆盖率为整工程口径（表述风险）**：99.65%/99.34% 非模块一/二单独数字，评审时若说成「供应商/状态机模块覆盖率」属不精确。**建议**：报告分域覆盖率时用 jacoco 按包（`controller`/`service.impl`/`calculator`）出细分表。
6. **三项挂账未闭环**：`audit_log` 缺 `supplier_id` 列（有数据只能 ALTER）、`performance_evaluation_draft` 残表、跨供应商聚合端点③是否替换 fan-out——均「仅报备待批」，评审时须说明为**未闭环事项**而非已完成。
