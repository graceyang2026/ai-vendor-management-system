## 0. 通用约定（全接口一体适用）

- **Base URL**：`/api/v1`（api-spec §0）
- **鉴权**：除 `POST /api/v1/auth/login` 外，所有接口必须 Header 携带 `Authorization: Bearer <token>`；后端按角色强制校验（`@PreAuthorize` + `RoleGuard`），前端隐藏按钮只是体验优化，不是安全边界。
- **统一响应包裹**（`ApiResponse`，成功码以已实现代码为准）：

```json
{ "code": 0, "message": "success", "data": { } }
```

- **时间格式**：ISO-8601（如 `2026-10-13T10:00:00`）；日期字段 `yyyy-MM-dd`。
- **字段命名**：请求/响应 JSON 物理维持 snake_case。
- **乐观锁**（§0 裁决 20261013 全量四实体）：`Supplier`、`PerformanceEvaluation`、`SupplierQualification`、`LifecycleRequest` 响应体均带 `version`；写操作必须回传，不匹配返回 `40901`。

## §1.1 供应商建档

# 模块二 · 状态机流转（6 接口）

> 本模块是**唯一能改 `supplier.status` 的入口**（无 PATCH 旁路）；三把门（audit / review / decision）均带 `version` 乐观锁。状态机：`DRAFT → PENDING_REVIEW → NORMAL ⇄ SUSPENDED → ELIMINATED`（终态）/ `RETURNED` 重提环。

## §2.1 提交准入审核

#### 1. 接口基本信息
- **接口路径**: `POST /api/v1/suppliers/{id}/submit`
- **请求方式**: `POST`
- **鉴权与角色**: `Authorization: Bearer <Token>`，允许角色：`STAFF`（仅本人档案）
- **业务约束与铁律**:
  - 状态迁移：`DRAFT` / `RETURNED` → `PENDING_REVIEW`。
  - 前置硬门槛：该供应商名下**至少一份未过期 `BUSINESS_LICENSE` 资质**（`expiry_date >= 今天`），否则 `40001`。
  - **请求体仅 `version` 一字段**（裁决 20261013 候选 B）：状态迁移统一纳入乐观锁并发控制范畴，防多端脏写；原口径“无 body”已作废。

#### 2. 请求参数 (Request)

##### Path Parameters
| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | `Long` | 是 | 供应商 ID |

##### Request Body (`application/json`)（`SupplierSubmitRequest`，裁决 20261013 候选 B）
```json
{
  "version": 1
}
```

##### Body 字段说明
| 字段名 | 类型 | 必填 | 枚举/校验规则 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `version` | `Integer` | 是 | `>= 1` | 乐观锁，取 `SupplierResponse.version`（DB 列 `supplier.version`）；缺失或不匹配 `40901` |

#### 3. 响应参数 (Response)

##### 成功响应（`HTTP 200 OK`）
```json
{
  "code": 0,
  "message": "success",
  "data": { "id": 1001, "status": "PENDING_REVIEW", "version": 2, "risk_warning": false }
}
```
- `data` = **SupplierResponse**（全 20 字段见附录 A1）。`status` 由本接口写入 `PENDING_REVIEW`；`version` 自增后回传，供后续 §2.2 审核使用。

##### 审计留痕
| 字段 | 取值 |
| :--- | :--- |
| `action` | `SUBMIT` |
| `entity_type` | `SUPPLIER` |
| `entity_id` | 供应商 ID |

#### 4. 异常响应与错误码矩阵

| HTTP | 业务 Code | 错误信息（Message） | 触发场景 |
| :--- | :--- | :--- | :--- |
| `400` | `40001` | `请先上传有效期内的营业执照` | 无未过期营业执照资质 |
| `403` | `40301` | `无权限` | 非 `STAFF` 角色 |
| `403` | `40302` | `当前状态不允许该操作` | 状态非 `DRAFT`/`RETURNED`，或档案非本人私有 |
| `404` | `40401` | `资源不存在` | 供应商 ID 不存在 |
| `409` | `40901` | `数据已被他人修改，请刷新后重试` | `version` 缺失或不匹配（裁决 20261013 候选 B） |

## §2.2 准入审核决策（连带批复资质）

#### 1. 接口基本信息
- **接口路径**: `POST /api/v1/suppliers/{id}/audit`
- **请求方式**: `POST`
- **鉴权与角色**: `Authorization: Bearer <Token>`，允许角色：`AUDITOR`
- **业务约束与铁律**:
  - 只能对 `status=PENDING_REVIEW` 的供应商审核，其余 `40302`（非法状态审核，裁决 20261013 与 §2.3/§3.3 同口径）。
  - **同事务连带**：`APPROVE` → 该供应商全部 `PENDING` 资质批量置 `APPROVED`；`REJECT` → 本批 `PENDING` 资质连带置 `REJECTED`（方案 A，整改后重传新件）。准入期资质**不调用 §2.3**。
  - 乐观锁：请求体必须回传 `version`（取 SupplierResponse.version），不匹配 `40901`。

#### 2. 请求参数 (Request)

##### Path Parameters
| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | `Long` | 是 | 供应商 ID |

##### Request Body (`application/json`)
```json
{
  "version": 2,
  "decision": "REJECT",
  "comment": "营业执照已过期，请更换后重新提交。"
}
```

##### Body 字段说明（`SupplierAuditDecisionRequest`）
| 字段名 | 类型 | 必填 | 枚举/校验规则 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `version` | `Integer` | 是 | `>= 1` | 乐观锁版本，取 SupplierResponse.version |
| `decision` | `String` | 是 | `APPROVE` / `REJECT` | 审核决策 |

# 裁决记录与样例差异

## 一、已拍板并闭口的两项（2026-10-13 11:17 用户裁决，api-spec 已同批修改）

1. **`LifecycleRequestResponse` 补 `version`——选候选 A（已落地）**
   - 用户架构理由：DDL 早已存在 `lifecycle_request.version` 物理列，且 §2.6 终审与状态机变更强依赖乐观锁；契约漏字段会使前端在并发修改/二次提交时缺少合规取值链——必须补齐。
   - 落地位置：`docs/api-spec.md` §3 `LifecycleRequestResponse` 新增 `version: number`（含取值链注释）；本档附录 A3 改为 **13 字段**；§2.6 入参说明同步指向 §2.5 列表返回值。

2. **§2.1 `submit` 纳入乐观锁——选候选 B（已落地）**
   - 用户架构理由：草稿抢提交概率虽低，但企业级 SRM 多端场景需防脏写与状态机冲突；状态迁移操作同样应纳入版本号并发控制。
   - 落地位置：`docs/api-spec.md` §2 新增 `SupplierSubmitRequest { version }` + 接口表 submit 行改写（缺失/不匹配 → `40901`）；本档 §2.1 补请求体表与错误码行；头部错误码总表 `40901` 触发位置增加 §2.1。
   - 实现约束（待开发启动后执行，本档仅登记）：供应商侧 `Supplier` 实体需标注 `@Version`，否则乐观锁拦截器不生效（已知 pitfalls：“拦截器与 DDL 就绪但零实体标注导致 40901 死码”）。

## 二、模板样例字段 ≠ 项目契约（保持不变，一律以契约为准）
   - 成功包裹码：模板样例 `code: 20000` ↔ 已实现 `ApiResponse.SUCCESS = 0`（本档用 0）。
   - 复核入参：模板样例 `action` / `review_comments` ↔ 契约 `decision` / `comment`（§3.3）。注意 §2.3 资质审批的入参才叫 `action` / `review_comment`（无 s）。
   - 评级字段：模板样例 `rating` ↔ 契约 `grade`；模板样例 `period: "2026-Q3"` ↔ 契约 `period_start` + `period_end`（无周期编码列）。
   - 状态枚举：模板样例响应写 `APPROVED / REJECTED` ↔ 契约绩效三态 `PENDING_REVIEW / APPROVED / RETURNED`（本档按契约）。
