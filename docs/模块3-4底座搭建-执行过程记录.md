## 三、模块 4：审计与日志（AuditLog）

### 3.1 契约收集
- `schema.sql` 第 7 节 `audit_log` 表：11 列，**无 operator_name 列**（只插入不更新）
- `docs/api-spec.md` 第 5 节：`AuditLogResponse` 接口定义 + `GET /api/v1/audit-logs?entity_type=&entity_id=&page=&page_size=`（ALL 角色可查，后端不做行级隔离）
- 关键推论：响应含 `operator_name` 但表不存 → **list() 须经 UserMapper 批量反查 sys_user.real_name**

### 3.2 TDD 过程
- **Red**（3 个测试类先行）：
  1. `AuditLogServiceImplTest`（4 例）：核心铁律 `recordNeverPropagatesMapperFailures`（Mock insert 抛 RuntimeException → `doesNotThrowAnyException`）；`recordPersistsAllContractFields`（捕获实体逐字段断言）；`listFiltersByEntityTypeAndIdAndSortsByCreatedAtDesc`（捕获 Wrapper 断言 ORDER BY created_at + 参数下推 + 姓名反查）；空页不触发反查
  2. `AuditLogControllerTest`（2 例）：standalone MockMvc，snake_case 参数默认值透传 + 响应 data.page_size
  3. `AuditLogResponseJsonTest`（2 例）：裸 ObjectMapper 全字段 snake_case + doesNotContain camelCase；三枚举 containsExactly 锁定
- **Green**（9 个主文件）：
  - `com.srm.core.audit`：EntityType(4值)/AuditResult(2值)/AuditAction(7值)/AuditLog 实体
  - `dto.auditlog.AuditLogResponse`：12 字段显式 @JsonProperty
  - `mapper.AuditLogMapper`（BaseMapper）、`service.AuditLogService`、`service.impl.AuditLogServiceImpl`、`controller.AuditLogController`
- **踩坑修复**（2 处编译错误，均改测试侧）：
  1. 纯 Mockito 环境 LambdaQueryWrapper 报 can not find TableInfo → `@BeforeAll` 中 `TableInfoHelper.initTableInfo(new MapperBuilderAssistant(new MybatisConfiguration(), ""), AuditLog.class)`
  2. `getParamNameValuePairs()` 不在 Wrapper 接口 → 强转 `AbstractWrapper`
- **验证**：`-Dtest=AuditLogServiceImplTest` 4/4 → 全量 **Tests run: 107, Failures: 0** / 行 99.01% / 分支 89.58%（新增防御分支，仍达标）/ Quality Gate PASSED

### 3.3 设计决策
| 决策 | 理由 |
|---|---|
| record() 整体 try-catch，仅 log.error | 契约铁律：审计写入绝不能影响主业务事务 |
| operator_name 查询期批量反查（非冗余存储） | 表结构契约无该列；selectBatchIds 一次取齐，realName 缺失回退 username |
| createdAt 由服务层 now() 填充 | 便于单测断言，与 DB 默认值等价 |
| Controller 路径 /api/v1/audit-logs | api-spec §5 完整路径优先于提示词简写 /audit-logs |
| 权限零配置 | SecurityConfig anyRequest().authenticated() 天然满足"所有已登录角色" |
| result 传 null 时默认 SUCCESS | 表列 NOT NULL DEFAULT 'SUCCESS' 对齐 |
