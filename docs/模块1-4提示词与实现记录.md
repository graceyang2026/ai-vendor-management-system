## 模块 1：登录及 Security 底座

### 1.1 原始提示词（节选）
```
@backend-dev 请实现 SRM 后端【模块 1：登录及 Security 底座】，严格遵循 docs/backend-interface-design.md
（第 8、9、10 节）与《SRM 底座功能契约文档》。
【落地范围】1. Common 基础组件（ApiResponse/ErrorCode 十码/BusinessException/GlobalExceptionHandler）
2. Security 组件（JwtTokenProvider、JwtAuthenticationFilter 校验失败仅放行、RestAuthenticationEntryPoint
→40101、RestAccessDeniedHandler→40301、CustomUserDetailsService、UserPrincipal）
3. POST /api/v1/auth/login（失败统一 40102）+ DemoUserSeeder（开关控制，空表播种 admin/staff01/auditor01）
4. 单元测试：./mvnw test 全过且行/分支覆盖率 > 85%
```

### 1.2 实现过程
- **Red**：15 个测试类先行（ApiResponse/ErrorCode/BusinessException/GlobalExceptionHandler/JwtTokenProvider/JwtAuthenticationFilter/双 Handler/CustomUserDetailsService/UserPrincipal/AuthServiceImpl/AuthController/DemoUserSeeder/TestController/集成测试）
- **Green**：26 个文件——common 6 类、security 6 类、登录链路（User 实体/UserMapper/LoginRequest/LoginResponse/AuthService(Impl)/AuthController）、config 3 类（SecurityConfig 无状态 JWT + @EnableMethodSecurity、MybatisPlusConfig 乐观锁插件、DemoUserSeeder）、pom/application.yml

- **验证**：Tests run: 71 全绿；行 99.01%（200/202）/分支 100%；curl 实机验证登录 0/40102/40101

### 1.3 关键决策
登录失败统一 40102 不暴露原因；Filter 校验失败只放行不抛异常（401 出口唯一）；40101→HTTP 401、40301→HTTP 403 双通道；测试 H2 用独立 schema-h2.sql；JWT 密钥环境变量化。

## 模块 2：权限拦截（RBAC）

### 2.1 原始提示词（节选）
```
请继续实现【模块 2：权限拦截（RBAC）】：
1. 捕获 40301：RestAccessDeniedHandler 返回 ApiResponse.error(ErrorCode.FORBIDDEN, "无权限")（40301/HTTP 403）
2. SecurityConfig 注册双 handler + 确保 @EnableMethodSecurity
3. Controller 层检查配置 @PreAuthorize（STAFF/AUDITOR/ADMIN hasRole）
4. 业务铁律：Controller 粗粒度拦截 + Service 层必须对「状态/本人」二次校验
   （如供应商仅【草稿/退回】允许 STAFF 编辑，【待审核】及以后强拒绝）
完成后运行 ./mvnw test 或门禁脚本验证
```

### 2.2 契约收集
- backend-interface-design.md §5 Controller @PreAuthorize 权限矩阵、§8「40301 由 RestAccessDeniedHandler」
- 契约 docx（textutil 转 txt）L109 关键句：**「40101/40301 由 Security 层处理，不经过 GlobalExceptionHandler」**

### 2.3 核心设计决策（契约纠偏）
模块 1 曾让 GlobalExceptionHandler 兜底 AccessDeniedException——与契约冲突。纠正为：
- **删除** advice 中的 AccessDenied handler；`handleUnknown` 改签名 `throws Exception`，遇 `instanceof AccessDeniedException` **原样重抛**
- 异常经 DispatcherServlet 冒泡到 ExceptionTranslationFilter → RestAccessDeniedHandler（403+40301 唯一出口），不被 catch-all 吞成 50001

### 2.4 TDD 过程
- **Red**：`CurrentUserProviderTest`（5 例）、`RoleGuardTest`（9 例）、`GlobalExceptionHandlerTest` 反射锁定（advice 禁止出现 AccessDeniedException 参数方法）、`AuthSecurityIntegrationTest` +11 例（角色矩阵 + `RbacDemoController` 测试控制器端到端）
- **Green**：新建 `CurrentUserProvider`（current()/require()）、`RoleGuard`（requireRole→40301 / requireStatusAllowed(false)→40302 / requireSelf→40302"仅限本人操作"）；改造 GlobalExceptionHandler
- **修复链**：测试方法数字开头编译错→重命名；handleUnknown 加 throws→测试补 throws Exception；@TestConfiguration 嵌套 @RestController 自动注册 + 手动 @Bean→Ambiguous mapping→删 @Bean；陈旧 surefire-reports 干扰→rm 重跑；grep 管道掩盖退出码→显式汇总
- **验证**：Tests run: 96 全绿（71→+25）；行 99.11% / 分支 100%；Quality Gate PASSED

### 2.5 交付文件
`security/CurrentUserProvider.java`、`security/RoleGuard.java`、修改 `common/GlobalExceptionHandler.java`；测试 +3 类 + 集成测试扩展。RoleGuard 为后续业务模块 Service 层复用组件。

## 模块 3：统一异常处理与 Common 通用组件

### 3.1 原始提示词（节选）
```
按契约文档模块 3 规范实现【统一异常处理与 Common 通用组件】：
一、ErrorCode 十码（SUCCESS(0)…LOGIN_FAILED(40102)…INTERNAL_ERROR(50001)）；
   ApiResponse：success(T)→code=0,message="success"；error(ErrorCode,String)；error(int,String)；
   PageResult：pageSize 显式 @JsonProperty("page_size")；BusinessException 持有 ErrorCode+message
二、GlobalExceptionHandler：BusinessException 透传；MethodArgumentNotValidException 动态提取
   getFieldError().getDefaultMessage()→40001；OptimisticLockingFailureException→40901"数据已被修改，请刷新后重试"；
   Exception：【核心防坑铁律】AccessDeniedException 必须原样重抛！其余打 log 返回 50001；
   RestAuthenticationEntryPoint：401 + JSON UTF-8 + 40101
三、单测验证 + ./mvnw test 全过
```

### 3.2 差异分析驱动（需求 vs 模块 1 已有）
| 需求 | 现状 | 动作 |
|---|---|---|
| LOGIN_FAILED(40102) | INVALID_CREDENTIALS 同值 | 重命名（主+测试 8 处） |
| success→"success" | "成功" | 改文案+断言 |
| error(int,String) | 只有 ErrorCode 版 | 新增重载 |
| @JsonProperty("page_size") | 依赖全局 SNAKE_CASE | 补显式注解 |
| 乐观锁文案 | "数据已被其他操作修改…" | 对齐契约措辞 |
| 重抛铁律/EntryPoint | 模块 2/1 已实现 | 补直接单测/无改动 |

### 3.3 TDD 与验证
- Red：5 个测试文件先改，新增 `errorWithRawIntCodeKeepsValue`、`pageResultSerializes...WithoutGlobalNamingStrategy`（裸 ObjectMapper）、`handleUnknownRethrowsAccessDenied...`（isSameAs 断言）
- Green：ErrorCode/ApiResponse/PageResult/GlobalExceptionHandler/AuthServiceImpl
- **验证**：Tests run: 99 全绿（96+3）；行 99.11% / 分支 100%；PASSED
- 插曲：两次收到"回退命名"的 IDE 附件 diff，grep 磁盘核实均**未落盘**——按磁盘真实状态+原始需求处理，沉淀 tool_experience 记忆

## 模块 4：审计与日志（AuditLog）

### 4.1 原始提示词（节选）
```
按契约文档模块 4 规范实现【审计与日志】：
一、com.srm.core.audit：EntityType(4值)/AuditResult(2值)/AuditAction(7值)/AuditLog 实体映射 audit_log 表；
   AuditLogResponse 12 字段全部显式 @JsonProperty snake_case
二、AuditLogService：record(EntityType,Long,UserPrincipal,String action,String oldStatus,String newStatus,
   AuditResult,String comment) + list(entityType,entityId,page,pageSize)→PageResult
   【核心隔离铁律】record 内部 insert 必须 try-catch 完全包裹，任何异常只 log.error，
   绝对禁止上抛导致主业务事务回滚
三、AuditLogController：GET /audit-logs（api-spec §5），所有已登录角色可访问，参数 entity_type/
   entity_id/page(默认1)/page_size(默认10)，返回 ApiResponse<PageResult<AuditLogResponse>>
四、AuditLogServiceImplTest 必须含 recordNeverPropagatesMapperFailures；./mvnw test 全过
```

### 4.2 契约收集与关键推论
- schema.sql 第 7 节：`audit_log` 11 列（操作类型列名为 **action**，答疑确认无 action_type），**无 operator_name 列**
- api-spec §5 完整路径 `/api/v1/audit-logs`
- 推论：响应需 operator_name → **list() 经 UserMapper.selectBatchIds 批量反查 sys_user.real_name**（缺失回退 username，空页不触发）

### 4.3 TDD 过程
- **Red**（3 测试类 8 例先行）：`AuditLogServiceImplTest`（铁律用例 doesNotThrowAnyException + 实体逐字段捕获 + Wrapper 断言 ORDER BY created_at/条件下推 + 空页）、`AuditLogControllerTest`（standalone MockMvc 默认值透传 + data.page_size）、`AuditLogResponseJsonTest`（裸 ObjectMapper 全字段 snake_case + doesNotContain camelCase；三枚举 containsExactly）
- **Green**（9 主文件）：audit 包 4 类、dto/auditlog、mapper、service+impl、controller
- **踩坑**：①纯 Mockito 无 SqlSession，LambdaQueryWrapper 报 can not find TableInfo → @BeforeAll `TableInfoHelper.initTableInfo(new MapperBuilderAssistant(new MybatisConfiguration(), ""), AuditLog.class)`；②getParamNameValuePairs() 仅 AbstractWrapper 有 → 强转
- **验证**：`-Dtest=AuditLogServiceImplTest` 4/4 → 全量 **Tests run: 107 全绿**（99+8）；行 99.01% / 分支 89.58%（新增防御分支仍达标）；PASSED

### 4.4 设计决策
record 整体 try-catch 仅 log.error；operator_name 查询期反查不冗余存储；createdAt 服务层 now()；完整路径 /api/v1/audit-logs 优先；权限零配置（anyRequest().authenticated() 天然满足）；result 传 null 默认 SUCCESS 对齐表列。
